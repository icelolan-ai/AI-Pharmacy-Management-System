# Phase 5 Gate — รายการตรวจก่อนปิดเฟส

เอกสารนี้มี 2 ส่วน

1. **รายการทดสอบด้วยมือ** — ผู้ใช้ทำเองหน้าจอจริง เขียนเป็นขั้นตอนสั้น ๆ ว่าต้องกดอะไร และผลที่ถูกต้องคืออะไร
2. **สรุป Phase 5** — ทำอะไรไปบ้าง, commit, เทสต์ทั้งหมด, และของที่ยังไม่ได้ทำ

---

## ส่วนที่ 1 — รายการทดสอบด้วยมือ

### เตรียมตัวก่อนเริ่ม

| สิ่งที่ต้องมี | รายละเอียด |
|---|---|
| หน้าเว็บ | `http://localhost:3000` |
| บัญชี | อย่างน้อย 2 บัญชี **คนละ role** เช่น `owner` 1 คน กับ `staff` 1 คน |
| ข้อมูลร้าน | กรอกไว้แล้วที่หน้า “ข้อมูลร้าน” |
| ยาและผู้จำหน่าย | มีอย่างน้อยอย่างละ 1 รายการ |

**วิธีใช้ตาราง:** ทำตามช่อง “ต้องกดอะไร” ทีละบรรทัด แล้วเทียบกับช่อง “ผลที่ถูกต้อง”
ถ้าตรง = ผ่าน, ถ้าไม่ตรง = จดไว้ว่าหน้าไหน ข้อไหน และเห็นอะไรแทน

> ระหว่างทดสอบ ถ้าเจอข้อความ **“ยังไม่มีการตัดสต็อก”** หรือ **“ยังไม่มีการรับเข้าคลัง”**
> แปลว่าระบบบันทึกไม่สำเร็จ **และไม่ได้แตะสต็อกเลย** — ปลอดภัย กดใหม่ได้

### T1 — เข้าระบบ ออกจากระบบ และสลับผู้ใช้คนละ role 🔴 ข้อสำคัญที่สุด

ข้อนี้ตรวจว่าชื่อและสิทธิ์ของคนเก่าไม่หลงค้างมาให้คนใหม่เห็น

| # | ต้องกดอะไร | ผลที่ถูกต้อง |
|---|---|---|
| 1 | เปิด `http://localhost:3000` แล้ว login ด้วยบัญชีแรก | เข้าหน้าแรกได้ · **มุมขวาบน**ขึ้นชื่อและตำแหน่งของบัญชีแรก · เมนูซ้ายขึ้นครบตามตำแหน่งนั้น |
| 2 | กด **F5** (refresh หน้าเว็บ) | ชื่อและตำแหน่งเดิมกลับมาเหมือนเดิม · **ต้องไม่ค้าง**ที่คำว่า “กำลังโหลดสิทธิ์...” · ไม่เด้งออกไปหน้า login |
| 3 | กดปุ่ม **ออกจากระบบ** (มุมขวาบน) | เด้งไปหน้า login ทันที · ชื่อผู้ใช้หายไปจากมุมขวาบน |
| 4 | login ด้วยบัญชีที่สอง (**คนละ role**) | ชื่อและตำแหน่งเป็นของ**คนใหม่ทันที** · เมนูซ้ายเปลี่ยนตามสิทธิ์ของคนใหม่ · **ต้องไม่เห็นชื่อหรือเมนูของคนเก่าแม้แวบเดียว** |
| 5 | ระหว่างข้อ 4 ให้จ้องมุมขวาบนตอนกด login | ถ้าเห็นชื่อคนเก่ากระพริบขึ้นมาก่อน = **ไม่ผ่าน** ให้จดไว้ |

| 7 | ลองสร้างใบใหม่แล้ว**ทิ้งไว้ไม่ยืนยัน** จากนั้นสร้างอีกใบและยืนยัน | เลขที่ใบรับของใบที่ยืนยัน **ต้องไม่ข้ามเลข** (ใบที่ทิ้งไม่กินเลข) |

### T6 — ปรับจำนวนสต็อก และการชนกัน (D23) 🔴

ข้อ 4–7 คือหัวใจ: ถ้ามีคนขายยาตัวเดียวกันระหว่างที่เราเปิดหน้าต่างปรับอยู่
ระบบต้องไม่ยอมบันทึกทับ **และต้องไม่ลบสิ่งที่เราพิมพ์ไปแล้ว**

| # | ต้องกดอะไร | ผลที่ถูกต้อง |
|---|---|---|
| 1 | **คลังยา** → กดชื่อยา → เลือกล็อต → ปุ่มปรับจำนวน | กล่องเปิดมา แสดง “จำนวนในระบบตอนนี้” ตรงกับที่เห็นในตาราง |
| 2 | ใส่จำนวนที่นับได้ เลือกเหตุผล กดบันทึก | บันทึกสำเร็จ · จำนวนในตารางเปลี่ยนตาม |
| 3 | เลือกเหตุผล **“อื่น ๆ”** แล้วเว้นช่องรายละเอียดว่าง | ปุ่มบันทึก**กดไม่ได้** · มีข้อความบอกว่าต้องกรอกรายละเอียด |
| 4 | เปิด**เบราว์เซอร์อีกหน้าต่าง** ไปหน้าขายยา แล้วขายยาตัวเดียวกันออกไป 1 ชิ้น | ขายสำเร็จ |
| 5 | กลับมาหน้าต่างแรก (กล่องปรับจำนวนยังเปิดค้างอยู่) พิมพ์จำนวนที่นับได้ เลือกเหตุผล พิมพ์รายละเอียด แล้วกดบันทึก | ขึ้นข้อความ **“จำนวนคงเหลือเปลี่ยนไประหว่างที่เปิดหน้าต่างนี้ กรุณาตรวจนับใหม่”** |
| 6 | ดูในกล่องที่ยังเปิดอยู่ | **จำนวนที่พิมพ์ · เหตุผลที่เลือก · รายละเอียดที่พิมพ์ ต้องยังอยู่ครบทั้ง 3 อย่าง** 🔴 · และ “จำนวนในระบบตอนนี้” เปลี่ยนเป็นเลขจริงล่าสุดแล้ว |
| 7 | กดบันทึกซ้ำอีกครั้งโดย**ไม่ต้องพิมพ์อะไรใหม่** | บันทึกสำเร็จ · ผลต่างคิดจากเลขจริงล่าสุด |

สิทธิ์ปัจจุบันถูกต้องอยู่แล้ว: staff ไม่ควรเห็นประวัติรับสินค้าและต้นทุน
โค้ดซ่อนคอลัมน์ที่ไม่เคยทำงานถูกลบออกแล้วจากทั้งหน้ารายการและหน้ารายละเอียด
และ D32 ในทะเบียนคำวินิจฉัยแก้เป็น “จำกัดที่ระดับหน้า ด้วย `viewReports`”
การป้องกันย้ายไปอยู่ที่ `history-access.check.mjs` ซึ่งอ่านตารางสิทธิ์จริง
ไม่ได้เขียนค่าซ้ำ — ถ้าวันหนึ่งมีคนเพิ่ม staff เข้า `viewReports` เทสต์จะ FAIL ทันที

**D33 — เก็บโค้ดตายครบทุกหน้าแล้ว**

หน้าที่กั้นด้วยด่านทุกหน้าในแอป ใช้สิทธิ์ที่เป็นสับเซ็ตของ `viewCost` ทั้งหมด
ชั้นสองที่เช็ค `viewCost` ข้างในจึงเป็นจริงเสมอ = โค้ดตาย ลบออกหมดแล้วจาก

| หน้า | ที่ลบ |
|---|---|
| ภาพรวมร้าน | `canSeeValue` + prop ของ `RiskSummaryCards` |
| ใกล้หมดอายุ | `canSeeValue` + prop ของ `ExpiringTable` |
| หมดอายุแล้ว | `canSeeValue` (คอลัมน์มูลค่า + กล่องสรุปความสูญเสีย) |
| ประวัติการขาย รายการ | `canSeeValue` (คอลัมน์ยอดรวม) |
| ประวัติการขาย รายละเอียด | `canSeeValue` (คอลัมน์ราคา/รวม + ยอดรวม) |
| ประวัติรับสินค้า ทั้งสองหน้า | `canSeeCost` (ลบไปแล้วใน D32) |

> 🔴 **ห้ามลบของ 3 หน้านี้** — `/stock`, `/stock/[id]`, `/sell`
> ทั้งสามไม่มีด่านกั้นหน้า staff เปิดได้จริงทุกวัน
> `canSeeValue` / `canSeeCost` / `canSeePrice` ในสามหน้านี้ **ทำงานจริง**
> ลบแล้วพนักงานขายจะเห็นต้นทุนที่ร้านจ่าย
> `history-access.check.mjs` จะ FAIL ทันทีถ้ามีคนลบ
